Variational Operator Layer (Internal)

Not exported: the linear operators, observation backends, cost function and Gauss–Newton/CG driver the problem is assembled from. Stable enough to build custom problems on, but qualified (Daisho.) and subject to change. The public API built on them is on the Variational Wind Analysis page.

Daisho.AbstractLinearOp — Type
AbstractLinearOp

Supertype of the variational solver's linear operators. A concrete operator op of size (m, n) implements

  • apply!(y, op, x): y = op·x (length(x) == n, length(y) == m),
  • apply_adjoint!(x, op, y): x = opᵀ·y,
  • Base.size(op)::Tuple{Int,Int}.

Both applications overwrite their output and must not alias input and output.

Daisho.ChainOp — Type
ChainOp(ops::AbstractLinearOp...)

Product ops[1] · ops[2] · … · ops[end], applied right to left like matrix multiplication: ChainOp(S, D, F) applies F, then D, then S. The adjoint applies Sᵀ, then Dᵀ, then Fᵀ. Intermediate buffers are allocated once at construction: bufs[k] (k = 1:length(ops)-1) holds the vector between ops[k+1] and ops[k], so length(bufs[k]) == size(ops[k], 2). Adjacent sizes are checked at construction (DimensionMismatch).

Daisho.DiagonalScaling — Type
DiagonalScaling(sigma::AbstractVector{<:Real}, npts::Integer)
DiagonalScaling(sigma::AbstractVector, npts::Integer)

Square diagonal operator on a variable-major vector of length(sigma) variables with npts points each. Entry sigma[v] is either a scalar (the same scale at every point of variable v) or a length-npts vector (a per-point map). All scales must be finite and strictly positive. The operator is symmetric, so the adjoint equals the forward application.

Daisho.SplineProjection — Type
SplineProjection(grid, varnames::Vector{String}; nchunks = Threads.nthreads())

Tensor-product spline projection S (per axis SA∘SB, applied along k, then j, then i) from a variable-major mish vector (per variable (kDim, jDim, iDim) column-major) to a variable-major coefficient vector (per variable (b_kDim, b_jDim, b_iDim) column-major). varnames selects and orders the variables among grid.params.vars. The resulting coefficients satisfy each variable's boundary conditions exactly. apply_adjoint! applies the exact transpose Sᵀ (i, then j, then k; per pencil sa! then sbt!).

Pencil sweeps run in nchunks tasks; results do not depend on nchunks.

Daisho.SplineEvaluation — Type
SplineEvaluation(grid, varnames::Vector{String}, slots::Vector{Tuple{Int,Int}};
                 lattice = :mish, nchunks = Threads.nthreads())

Tensor-product spline evaluation from a variable-major coefficient vector (as produced by SplineProjection for the same varnames) to the requested (var_index, slot) slabs on the evaluation lattice, concatenated in the order given. var_index indexes varnames; slot is 1 = value, 2 = ∂/∂i (x), 3 = ∂/∂j (y), 4 = ∂/∂k (z). apply_adjoint! scatters the slabs back through the same branches and accumulates into the (zeroed) coefficient vector.

lattice = :mish evaluates at the grid's quadrature points (each slab has iDim·jDim·kDim entries in the mish layout, k fastest); lattice = :nodes evaluates at the B-spline nodes LinRange(min, max, cells + 1) of every axis (node_coordinates; (cells_k+1)·(cells_j+1)·(cells_i+1) entries per slab, same k-fastest layout) — the default regular output grid and the mass-continuity lattice of mass_continuity_lattice = "nodes". lattice_dims gives the slab shape.

See also: slab_view

Daisho.coefficients_to_springsteel_spectral! — Function
coefficients_to_springsteel_spectral!(grid, a, varnames) -> grid.spectral

Write Daisho coefficients a (variable-major, per variable (b_kDim, b_jDim, b_iDim) k-fastest, satisfying each variable's BCs — e.g. the output of SplineProjection) into grid.spectral so that Springsteel.gridTransform!(grid) reproduces the same field and derivatives.

Springsteel's spectral array stores SB outputs (B-vectors), i-fastest. Since a = Γᵀx along every axis, B = (P+Q)·a per axis satisfies SA(B) = Γᵀ(Γ(P+Q)Γᵀ)⁻¹Γ(P+Q)Γᵀx = a; this function applies (P+Q) along all three axes and permutes into spectral[(z-1)·b_jDim·b_iDim + (l-1)·b_iDim + i, v]. Columns of variables not in varnames are left untouched.

Daisho.AxisFilter — Type
AxisFilter(filter::Springsteel.AbstractFilter, ax::AxisSpline;
           normalisation = :variance, symmetric = false)

Sparse Dim×Dim matrix form of a Springsteel spline-direction filter (GaussianFilter or LanczosFilter; sigma/a in cell widths of ax.sp.DX) on the mish points of ax, with its materialised transpose Ft so both directions are CSC products.

  • symmetric = false (default) builds the row-normalised convolution F_row[i,j] = K(x_j − x_i)/W_i within the kernel support, exactly Springsteel's _convolve_axis! (F_row·1 = 1; a row whose weight sum is ≤ 0 is the identity row; not symmetric: see the file header), and then applies normalisation:
    • :variance (default, the solver's background-error filter): F = N⁻¹F_row with N = diag(√(Σ_j F_row[i,j]²)), so diag(F Fᵀ) = 1 exactly at every mish point (white noise keeps unit variance; sigma of D is then the background-error standard deviation). Row sums are no longer 1.
    • :row: F = F_row (Springsteel parity; mean-preserving smoothing).
  • symmetric = true (experimental; normalisation is ignored and the stored normalisation is :none — this variant is NOT variance-normalised): F = W_q^{1/2}·(K/κ)·W_q^{1/2} with the SB quadrature weights W_q = diag(ax.w) (DX·quadweights) and κ = ∫K over the support (so the kernel integrates to one; Springsteel's Lanczos kernel has K(0) = 1, ∫K ≈ DX), built on the upper triangle and mirrored, so it is exactly symmetric. There is no row normalisation: in the interior F·√w ≈ √w to the accuracy of the mish quadrature of ∫K/κ = 1, so constants are preserved (F·1 ≈ 1) only on a mish with uniform weights (regular quadrature); on a Gauss mish F·1 deviates by O(10%) with the in-cell weight pattern. Near boundaries the truncated window damps the output.

Kernel values that are exactly zero (Lanczos zero crossings and support edge) are not stored; the diagonal always is. SpectralFilter (and any other filter type) throws ArgumentError.

Fields: F, Ft, support (kernel half-width, metres), length_cells (Gaussian sigma or Lanczos a, in cells), symmetric, normalisation (:variance, :row, or :none for the symmetric variant).

Daisho.MishFilter — Type
MishFilter(grid, varnames, filters::AbstractMatrix{<:Union{Nothing,Springsteel.AbstractFilter}};
           normalisation = :variance, symmetric = false, nchunks = Threads.nthreads())
MishFilter(grid, varnames, lengths_cells::AbstractMatrix{<:Real};
           kind = :gaussian, n_sigma = 4, normalisation = :variance,
           symmetric = false, nchunks = Threads.nthreads())

Separable 3-D mish-space filter F on a variable-major mish vector (per variable (kDim, jDim, iDim) column-major; varnames selects and orders the variables of the RRR grid, as for SplineProjection). filters is 3 × nvars with rows 1 = k, 2 = j, 3 = i (the convention of the spline operators); nothing leaves that axis unfiltered, and a variable with no filter at all passes through unchanged. Each entry becomes an AxisFilter on that variable's axis spline with the given normalisation:

  • :variance (default; the background-error filter of the solver): every axis filter is variance-normalised, so the tensor product satisfies diag(F Fᵀ) = Π_axes diag(F_a F_aᵀ) = 1 exactly at every mish point — white control noise keeps unit variance and D's σ is the background-error standard deviation (before the spline projection).
  • :row: Springsteel's row-normalised convolution (F·1 = 1), for Springsteel parity and mean-preserving smoothing of fields.

symmetric = true (experimental) ignores normalisation and is not variance-normalised (filter_normalisation then returns :none).

The convenience form takes filter lengths in cells: kind = :gaussian (sigma = length, truncated at n_sigma·σ) or :lanczos (a = length, must be an integer); 0 or NaN means no filter on that axis. Use filter_lengths_cells to convert lengths in metres.

apply! sweeps k, then j, then i; apply_adjoint! applies the transposes in the order i, j, k. The input is never modified; input and output must not alias (ArgumentError). Results do not depend on nchunks.

See also: axis_filter, filter_length_cells, has_filter

Daisho.ObsSet — Type
ObsSet(grid, varnames, backends; nchunks = Threads.nthreads())

The union of observation backends acting on the coefficient vector of the state variables varnames of the RRR grid (the same grid/varnames as the SplineProjection). Observations are concatenated in backend order (ranges[b] is backend b's block); y and rinv hold the concatenated values and inverse variances.

One SplineEvaluation ev is built for the union ev_slots of the (var, slot) pairs used by all mish-lattice backends (nothing if there are none), and a second one (ev_nodes, ev_nodes_slots) for the node-lattice backends (MishObsBackend with lattice = :nodes); slab_map[b] maps backend b's slots to indices in its lattice's slot list (empty for scattered backends).

ObsSet <: AbstractLinearOp of size (nobs, nvars·ncoef): apply!(y, set, a) = apply_H!, apply_adjoint!(a, set, y) = apply_Ht!. Mish observations are processed in nchunks tasks (chunks never split a mish point, so the adjoint scatter is race-free and the results do not depend on nchunks); nchunks = 1 is allocation-free.

See also: evaluate!, linearize!, cost_by_backend

Daisho.MishObsBackend — Type
MishObsBackend(kind::Symbol, dims::Tuple{Integer,Integer}, points, y, rinv,
               terms::AbstractVector{<:AbstractVector{<:Tuple{Integer,Integer,Real}}};
               model = nothing, lattice = :mish)
MishObsBackend(kind, grid, varnames, points, y, rinv, terms; model = nothing, lattice = :mish)

Observations located on an evaluation lattice of the state grid — the mish (lattice = :mish, the quadrature points) or the B-spline nodes (lattice = :nodes, see SplineEvaluation) — stored structure-of-arrays and sorted (stably) by point. dims = (nvars, npoints) gives the number of state variables and of lattice points per variable (the second form takes them from the RRR grid and varnames, as for SplineProjection). For observation m: points[m] ∈ 1:npoints is the lattice flat index (k fastest), y[m] the value, rinv[m] = 1/σ² (> 0, see inverse_variance), and terms[m] a non-empty list of (var, slot, weight) with var ∈ 1:nvars and slot ∈ 1:4 (1 = value, 2 = ∂x, 3 = ∂y, 4 = ∂z). A linear observation is h_m(a) = Σ_t weight_t · slab(var_t, slot_t)[point_m].

kind is a free diagnostic label (e.g. :radial_velocity, :mass_continuity, :point, :wind_speed).

Nonlinear hook. model(sample, m) -> (value, weights): sample[s] is the current value of slots[s] (every slot this backend uses, in the order of the slots field) at observation m's point; value is h_m(a) and weights (any indexable of length length(terms[m])) the tangent-linear weights of m's terms, in the order given at construction. m is the ORIGINAL (construction-order) observation index. Linearisation (through the ObsSet) overwrites the stored weights; the initial weights in terms are used until the first linearisation. model === nothing ⇒ linear.

Fields (sorted order): point, y, rinv, term_ptr (CSR, length nobs+1), term_slab (index into slots), term_w, slots, model, kind, perm (perm[m] = original index of sorted observation m), nvars, nmish (lattice points per variable), lattice. Nonlinear models are supported on the mish lattice only.

source
Daisho.ScatteredObsBackend — Type
ScatteredObsBackend(kind::Symbol, grid, varnames, xyz::AbstractMatrix, y, rinv,
                    terms::AbstractVector{<:AbstractVector{<:Tuple{Integer,Integer,Real}}})

Linear observations at arbitrary points xyz[m, :] = (x, y, z) (metres, the grid's i, j, k coordinates) inside the domain of the RRR grid; varnames selects and orders the state variables as for SplineProjection. Terms, values and rinv = 1/σ² are as for MishObsBackend.

The operator is stored as a sparse nobs × (nvars·ncoef) matrix H (and its transpose Ht): each term (var, slot, w) contributes the 4×4×4 tensor-product stencil w·φ_i^{(dᵢ)}(x)·φ_j^{(dⱼ)}(y)·φ_k^{(dₖ)}(z) (first derivative on the slot's axis, values elsewhere) at the Daisho coefficient indices (var−1)·ncoef + mk + (mj−1)·b_kDim + (mi−1)·b_kDim·b_jDim, with the node range of Springsteel's single-point SItransform.

Points outside [min, max] on any axis throw ArgumentError (callers pre-filter). Linear only.

Daisho.IncrementalCostFunction — Type
IncrementalCostFunction(C::AbstractLinearOp, obs::ObsSet, a_g::AbstractVector)

Incremental cost function for the control-to-coefficient operator C (size (ncoef_total, n), ChainOp(S, D, F) in production), the observations obs (acting on coefficients, size(obs, 2) == size(C, 1)), and the background coefficients a_g (e.g. apply!(a_g, S, x_g)).

Fields: C, obs, a_g, ξ_total (accumulated control increment, starts at 0), a_k = a_g + C ξ_total at the current linearisation, d = y − h(a_k) (innovation), rhs = Cᵀ H_kᵀ R d − ξ_total, plus scratch vectors. The constructor linearises at ξ_total = 0 (relinearize!).

See also: hessian_mul!, cost, cost_nonlinear, gradient!, HessianOperator, solve_incremental!

Daisho.solve_incremental! — Function
solve_incremental!(cf::IncrementalCostFunction, opts = VarSolverOptions()) -> VarSolverStats

Minimise the incremental cost by Gauss–Newton outer iterations, each solving the linear SPD system (I + CᵀH_kᵀRH_kC) δξ = rhs with Krylov.cg! (one reused CgWorkspace, x0 = 0). Resets and then accumulates cf.ξ_total; on return cf.a_k, cf.d, cf.rhs refer to the LAST linearisation (not the final state). Use analysis_coefficients! for a_g + C ξ_total.
