Variational Wind Analysis (Stage 2)

The incremental 3DVAR (u, v, w) analysis built on the stage-1 WindGridAccumulator. See the Variational Wind guide for configuration and workflow, and the theory page for the mathematics. The [variational] configuration structs (VariationalParameters and its sub-tables) are listed on the Parameters page.

Pipeline

Daisho.analyze_radar_volumes_variational — Function
analyze_radar_volumes_variational(volumes::AbstractVector{<:Volume}, output_file, index_time,
    sgrid::RRR_Grid, p::DaishoParameters; heading = -9999.0, institution = "", source = "",
    include_derivatives = false, frame = CartesianFrame(), reference = nothing,
    nchunks = Threads.nthreads(), write_output = true, return_problem = false)
    -> VariationalResult  (or (VariationalResult, VariationalProblem) with return_problem)
analyze_radar_volumes_variational(volume::Volume, output_file, index_time, sgrid, p; kwargs...)

The variational (3DVAR) wind analysis from radar volumes to a NetCDF file.

  1. Requires [variational] enabled = true (ArgumentError otherwise) and a grid whose variable map matches [fields] (as for grid_radar_volume_spectral).
  2. Centres the grid on the centroid of the volumes' reference positions (volume_reference_position), builds the accumulator on sgrid's quadrature lattice (build_springsteel_grid_spec, build_accumulator with the reference-density profile reference, default build_reference_profile(p, sgrid)) — a WindGridAccumulator, so one [fields] entry must carry the velocity tag (ArgumentError otherwise) — and grids every sweep of every volume.
  3. Runs the scalar spectral products on sgrid exactly as grid_radar_volume_spectral does (the scalar fields written are identical).
  4. Builds the VariationalProblem from the accumulator (stage-1 finalize_wind in frame, state vector, background, radial-velocity super-obs, mass continuity, scalar value obs), solves it (solve_variational) and loads the analysis into the state grid (evaluate_analysis!).
  5. With write_output = true, writes output_file with write_variational_netcdf; index_time (a DateTime, or nothing for no time dimension) becomes the file's time coordinate.

Returns the VariationalResult; with return_problem = true, the tuple (result, problem) so the stage-1 product (problem.stage1), the observation set and the state grid (holding the analysis) are reachable.

source
Daisho.write_variational_netcdf — Function
write_variational_netcdf(output_file, sgrid, prob::VariationalProblem,
    result::VariationalResult, volume::Volume, p::DaishoParameters;
    index_time = nothing, ref_lat, ref_lon, institution = "", source = "",
    heading = -9999.0, include_derivatives = false) -> output_file

Write the variational analysis and the gridded scalar fields to one CF-1.12 NetCDF file.

sgrid is the obs/scalar grid after its spectral transform (as left by analyze_radar_volumes_variational or grid_radar_volume_spectral); volume supplies the time-coverage metadata. p selects the optional outputs ([variational] output_background, output_increment, output_mish), so the same solve can be written with different settings.

Layout

The file is created by write_radar_netcdf (Springsteel's regular output grid: dims x, y, z, the scalar fields, grid_mapping, the radar global attributes), with time = index_time (a DateTime, or nothing for no time dimension). Every regular-grid field is Float64 with a NaN fill on ("time", "x", "y", "z") (Julia order; ("x", "y", "z") without time), exactly like the scalars. Appended:

  • Analysis (regular grid, from Springsteel's regularGridTransform of the analysis coefficients): U, V, W (the state's wind-role variables, by name; CF eastward_wind/northward_wind/upward_air_velocity). A [fields]-derived state variable (e.g. DBZ) is written as <name>_ANALYSIS, since <name> is the gridded scalar field.
  • VORT = ∂v/∂x − ∂u/∂y, DIV = ∂u/∂x + ∂v/∂y (s⁻¹), and — when the state has W — MCRESIDUAL = DIV + ∂w/∂z + w·d(ln ρ̄)/dz (s⁻¹, ρ̄ from prob.reference at the regular z).
  • include_derivatives = true: the six derivative fields of every analysis variable with Springsteel's scalar suffixes (_x, _xx, _y, _yy, _z, _zz).
  • output_background: <name>_BACKGROUND (the background coefficients a_g); output_increment: <name>_INCREMENT (analysis − background coefficients), so BACKGROUND + INCREMENT = analysis.
  • QFLAG (when the problem carries a stage-1 product, prob.stage1): the stage-1 bitwise quality flag (CF flag_masks/flag_meanings, see Daisho.QFLAG_MEANINGS) resampled from the quadrature lattice to the regular points by Daisho.regular_quality_flag with the rule [variational] quality_flag_map ("nearest", "worst", "best"); Int8, no fill, on the regular dims. It is stage 1's diagnosis of the per-point dual-Doppler geometry, not of the variational analysis: the solve can recover winds at points stage 1 flagged (baseline, a single σ above threshold) but has nothing to fit where there was no data.
  • Masking: when [variational] mask_quality_flags is non-empty, every regular-grid wind-derived field — the wind-role analysis variables (all derivative suffixes), their _BACKGROUND/_INCREMENT, VORT, DIV, MCRESIDUAL — is set to NaN where QFLAG carries any listed bit. Gridded scalars and <name>_ANALYSIS of scalar state variables are never masked. With the default empty list nothing is masked.
  • output_mish: dims x_mish, y_mish, z_mish (the quadrature coordinates) with <name>_MISH (Float64, the mish analysis result.analysis, exact), the stage-1 product (U_STAGE1, V_STAGE1, USTD, VSTD, DET, NGATES, and the flag itself as QFLAG_MISH — the QC'd product blanked where the flag != 0, Float32 with the [io] fill, as in write_wind_synthesis), NOBS_VR (Int8), all on ("time", "x_mish", "y_mish", "z_mish"), and RHOBAR on ("z_mish",) (the ρ̄ the continuity constraint used).

Global attributes: those of write_radar_netcdf plus variational_background, variational_outer_iterations, variational_cg_iterations (total CG iterations), variational_converged (1/0), variational_quality_flag_map (the resampling rule) and variational_mask_quality_flags (the masked flag meanings, space-separated; empty when none).

Mutates prob.state_grid.spectral (it holds the analysis coefficients on return); call from a single thread.

Daisho.Background — Type
Background(x::Vector{Float64}, sigma::Vector{Float64}, mode::Symbol)
Background(state::StateVector, p::DaishoParameters)                              # :zero
Background(state::StateVector, stage1_or_nothing, p::DaishoParameters)           # dispatch on config
Background(state::StateVector, state_grid, stage1_or_nothing, p::DaishoParameters;
           nchunks = Threads.nthreads())                                         # dispatch on config

The background (first guess) of the variational analysis and the diagonal D of its background-error chain C = S∘D∘F, both on the state mish.

Fields

  • x::Vector{Float64}: the mish-space background x_g, flat and variable-major like the state vector (length(state); see state_view). Its spline projection a_g = S x_g is the outer loop's starting point.
  • sigma::Vector{Float64}: the per-point background-error standard deviation (same layout), every entry finite and > 0 so D is positive definite. Because F is variance-normalised (diag(F Fᵀ) = 1), this is the actual per-point background-error standard deviation (before the spline projection).
  • mode::Symbol: :zero, :synthesis, :synthesis_uniform_sigma, :synthesis_profile, or :custom (the raw constructor's label for a caller-supplied background).

Modes ([variational] background, a flat vocabulary)

With σ each variable's configured [variational.background_error] σ and inflation = background_error_inflation:

  • "zero" → :zero (samurai-like): x = 0, sigma = σ (background_sigma_vector(state)). Any stage-1 product is ignored.
  • "synthesis" → :synthesis: U/V background = the smooth fit (synthesis_smooth_fit); σ map = the smoothed stage-1 σ map (synthesis_sigma_map), clamped to [σ/10, σ], times inflation. Other variables: x = 0, sigma = σ·inflation.
  • "synthesis_uniform_sigma" → :synthesis_uniform_sigma: the smooth fit, with sigma = σ·inflation for every variable.
  • "synthesis_profile" → :synthesis_profile: U/V background = the level-mean profile (synthesis_level_profile), constant on each mish level; sigma = σ·inflation for every variable.

W and scalar state variables have a zero background in every mode.

The smooth fit needs the state grid (it is one auxiliary variational solve), so "synthesis" and "synthesis_uniform_sigma" need the four-argument form; the three-argument form throws ArgumentError for them. Every synthesis* mode needs stage1 (nothing → ArgumentError).

stage1 must be the product of finalize_wind on the accumulator built on this state's mish (size(stage1.comp1) == state.dims, else DimensionMismatch), with the same output frame as the StateVector: its component_names must equal the names of the :wind_u/:wind_v state variables (ArgumentError otherwise). Note the radial-velocity super-obs always constrain Cartesian (u, v), so the synthesis* backgrounds are only meaningful with the default CartesianFrame.

Double counting. Stage 1 and the radial-velocity super-obs come from the same gates, so every synthesis* mode counts the radar data twice; background_error_inflation ≫ 1 weakens the background to compensate.

Daisho.synthesis_smooth_fit — Function
synthesis_smooth_fit(state, state_grid, stage1::SynthesisOutput, p; nchunks = Threads.nthreads())
    -> Vector{Float64}

The smooth-fit background of the "synthesis" and "synthesis_uniform_sigma" modes (flat, variable-major, length(state)): the spline field closest to the stage-1 (u, v) at unflagged points (quality_flag == 0), from one AUXILIARY variational solve with

  • a zero background and each variable's configured uniform σ, the configured (variance-normalised) mish filter, and the state grid's spline projection — the same C = S∘D∘F as a "zero" problem;
  • no mass continuity and no radar super-obs;
  • one linear value observation (ScalarValueObs, group kind :synthesis_fit) per good point and component: value stage1.comp1 (comp2), σ = max(stage1.sigma1 (sigma2), σ_U (σ_V)/100), so well-determined points dominate;
  • the inner solver settings of the main solve (solver_options(p) with max_outer = 1; the problem is linear).

The result is the spline analysis of that solve on the mish for U/V; all other variables are 0. In data gaps the fit relaxes smoothly to 0 over the filter length. Cost: one extra CG solve of the size of the main one. With no good stage-1 point the fit is 0 everywhere (@warn).

source
Daisho.synthesis_sigma_map — Function
synthesis_sigma_map(state, state_grid, stage1::SynthesisOutput, p; nchunks = Threads.nthreads())
    -> Vector{Float64}

The background-error σ of the "synthesis" mode (flat, variable-major). For U (and likewise V) with configured σ: start from s = stage1.sigma1 at good points (quality_flag == 0, finite σ) and s = σ at flagged points; smooth the VARIANCE map s² with the configured mish filter of that variable in its row-normalised (mean-preserving) form (MishFilter(…; normalisation = :row)); take the square root; clamp to [σ/10, σ]; multiply by background_error_inflation. Every other variable: σ · inflation.

source
Daisho.synthesis_level_profile — Function
synthesis_level_profile(state::StateVector, stage1::SynthesisOutput) -> (u::Vector{Float64}, v::Vector{Float64})

The level-mean stage-1 profile of the "synthesis_profile" mode, one value per mish level k (length state.dims[1]): the plain mean of stage1.comp1 (comp2) over the good points (quality_flag == 0) of that level. Levels without a good point are filled by linear interpolation in z_mish between the nearest levels that have one (constant extrapolation beyond the lowest/highest such level). If no level has a good point the profile is all zeros (@warn).

Daisho.solve_variational — Function
solve_variational(prob::VariationalProblem; opts = solver_options(prob.params)) -> VariationalResult

Run solve_incremental! on prob.cf (which resets and then accumulates ξ_total, so repeated calls are independent), then form the analysis coefficients, the mish analysis (one SplineEvaluation value pass), the mish increment D F ξ_total, and the per-kind observation cost at the analysis.

Daisho.VariationalResult — Type
VariationalResult

Output of solve_variational. All mish-space vectors are flat and variable-major (see state_view).

Fields

  • state::StateVector.
  • coefficients: analysis spline coefficients a_g + C ξ_total (Daisho layout; export with evaluate_analysis!).
  • analysis: the spline analysis evaluated on the mish (value slot of every variable) — the smooth, boundary-condition-exact analysis.
  • background: the mish background x_g.
  • increment: the mish-space increment D F ξ_total (before the spline projection, so NOT spline-smoothed; analysis ≈ S-smoothed(background + increment)).
  • control: ξ_total.
  • stats::VarSolverStats.
  • cost_by_group: ½ Σ r (y − h(a))² per observation kind at the analysis.
  • nobs_vr: the problem's super-obs row counts (or nothing).
  • converged::Bool.

Daisho.StateVector — Type
StateVector

The configured control-variable composition: an ordered list of StateVariables and the mish geometry they share.

Fields

  • vars::Vector{StateVariable}: state variables in [variational] state order.
  • dims::NTuple{3,Int}: mish dimensions (nz, ny, nx) = (kDim, jDim, iDim).
  • n_mish::Int: prod(dims).
  • offsets::Vector{Int}: variable v occupies offsets[v]+1 : offsets[v]+n_mish of the flat state vector.
  • index::Dict{String,Int}: state-variable name → v.
  • roles::Dict{Symbol,Int}: singular role (STATE_SINGULAR_ROLES) → v.
  • z_mish::Vector{Float64}: vertical mish coordinates (length dims[1]), ascending, shared by every (i, j) column of the grid.
  • node_dims::NTuple{3,Int}: (nz, ny, nx) of the B-spline node lattice (cells .+ 1 per axis — the default regular output grid and the mass_continuity_lattice = "nodes" constraint points); n_nodes its size; z_nodes the vertical node coordinates (length node_dims[1]).

See also: state_view, wind_indices, has_role, role_index, filter_lengths_m, background_sigma_vector, create_state_grid.

StateVariable

One control-variable entry: its role, units, provenance, background-error specification, mish-space filter length, resolved per-axis boundary conditions, and (for a [fields]-derived scalar) its value-observation parameters. Built by StateVector; not constructed directly except in tests.

Daisho.create_state_grid — Function
create_state_grid(p::DaishoParameters, sgrid::RRR_Grid, state::StateVector) -> RRR_Grid

Build the state grid: a Springsteel grid with the same geometry as sgrid (bounds, cell counts, mubar, quadrature, regular_out) but variables state_index_dict(state) and each state variable's own resolved boundary conditions (plan §3.3). Implemented as create_radar_grid(p.grid.springsteel, state_index_dict(state)), which independently reproduces sgrid's geometry from the same [grid.springsteel] config and fills BCL/BCR/BCD/BCU/BCB/BCT from the same per-variable bc_min/bc_max dicts state's boundary conditions were resolved from — so the two are consistent by construction; allowed widens to every configured [fields] name (not just state's), so a BC override meant for the obs/scalar grid's own fields does not spuriously fail state-grid construction. spline_filter is left empty (exports are not re-filtered).

Throws if the resulting grid's geometry disagrees with sgrid (a same-[grid.springsteel] precondition violation) or carries a spline_filter.

Daisho.AbstractStateTransform — Type
AbstractStateTransform

Daisho.AbstractObservation — Type
AbstractObservation

Supertype of variational observation types. Interface (the first four are required; the rest have defaults):

  • obs_value(o) -> Float64: the observed value.
  • obs_sigma(o) -> Float64: its standard deviation (> 0); obs_inverse_variance(o) = 1/σ² by default.
  • obs_location(o) -> ObsLocation: a MishIndex, NodeIndex or XYZ.
  • obs_terms(o, state::StateVector) -> Vector{ObsTerm}: the linear operator row (for nonlinear types, the initial linearisation).
  • obs_kind(o) -> Symbol: the group label (default: a per-type constant).
  • is_linear(o): true by default.
  • obs_slots(o, state): the distinct (var, deriv+1) of obs_terms, in term order — the sample layout of nonlinear types.

Daisho.radial_velocity_superobs — Function
radial_velocity_superobs(acc::WindGridAccumulator, state::StateVector, p::DaishoParameters)
    -> (group::ObsGroup{RadialVelocitySuperObs}, nobs_vr::Array{Int8,3})

Turn the stage-1 per-point normal systems into super-observations (plan §2). The accumulator planes must lie on the state mish (size(acc.AtWA)[2:4] == state.dims). At each point with gates and positive total weight, with S = Σ w g gᵀ and b = Σ w ṽ g:

  • the system is the full (u, v, w) 3×3 (requires a :wind_w state variable and acc.n_unknowns == 3, i.e. [synthesis] include_vertical_velocity = true), or its (u, v) 2×2 block when [variational.radial_velocity] horizontal_approximation = true (N = 2 or 3). A 3×3 whose S[3,3] == 0 exactly (every gate at zero elevation, so w is structurally unobserved) is reduced to the 2×2 block;
  • S = Σ_r λ_r e_r e_rᵀ; each r with λ_r > 0 and λ_r > eigenvalue_guard_relative · λ_max emits one RadialVelocitySuperObs with e = e_r (zero-padded to 3), value y_r = e_rᵀb / λ_r and σ_r = √(σ²_vr · error_inflation / λ_r) (inverse variance λ_r / (σ²_vr · error_inflation), σ²_vr = [synthesis] velocity_variance).

Then Σ_r r_r (e_rᵀx − y_r)² = Σ_m w_m (ṽ_m − g_mᵀx)² / σ²_vr + const (up to the guard-dropped directions): the rows reproduce the gate cost and its gradient 2(Sx − b)/σ²_vr exactly. Eigenvector signs are arbitrary; y_r flips with e_r, so each row (and its cost) is sign-invariant.

nobs_vr[k, j, i] ∈ 0:3 counts the rows per point (a diagnostic).

Daisho.VarSolverOptions — Type
VarSolverOptions(; max_outer = 1, max_inner = 200, inner_tolerance = 1e-4,
                 outer_tolerance = 1e-3, preconditioner = nothing,
                 history = true, report_interval = 0, io = stdout)

Options of solve_incremental!.

  • max_outer: Gauss–Newton (outer) iterations; 1 is exact for linear obs.
  • max_inner: CG iteration cap per outer iteration.
  • inner_tolerance: CG relative residual tolerance (rtol, relative to ‖rhs‖; atol = 0).
  • outer_tolerance: stop when ‖δξ‖ / max(‖ξ_total‖, eps) < outer_tolerance.
  • preconditioner: passed to Krylov.cg! as M. Krylov's convention: M approximates the INVERSE Hessian and is applied with mul!, except that a LinearAlgebra.Factorization (an approximation of the Hessian itself) is applied with ldiv! (ldiv = true). nothing ⇒ no preconditioner. Untested hook.
  • history: keep the CG residual norms of every inner solve.
  • report_interval: print solver progress to io — a header (control size, observation counts, initial cost split into J_b and per-backend J_o), one line per outer iteration (‖∇J‖, J_k), a CG line at iteration 1 and every report_interval CG iterations (‖r‖, ‖r‖/‖r₀‖, model cost J, ΔJ, elapsed time; see Daisho.cg_model_cost) and a summary after each CG solve. 0 (default) is silent. Reporting never changes the result.
  • io: destination of the progress lines.

Daisho.FallSpeedParameters — Type
FallSpeedParameters

Hydrometeor terminal fall-speed correction for the radial velocities entering the wind normal system, loaded from the optional [synthesis.fall_speed] sub-table (a present table means "enabled"; every key is optional and defaults as below). Mirrors samurai (VarDriver3D.cpp), with heights in metres and the density correction taken from the configured [reference_state] profile:

Z    = 10^(dBZ/10)                                  (linear reflectivity, mm⁶ m⁻³)
DCOR = (ρ̄(0)/ρ̄(z))^density_exponent                (Beard 1985 density correction)
V_R  = −rain_coefficient · Z^rain_exponent · DCOR   (Joss & Waldvogel 1971)
V_S  = −snow_coefficient · Z^snow_exponent · DCOR   (Atlas et al. 1973)

Fall speeds are in m/s and negative (downward); the corrected gate value is ṽ = v_r − w_t·sin(el). See terminal_fall_speed for the dBZ and melting-layer blending. Requires a [fields] entry tagged reflectivity.

Fields

  • rain_coefficient::Float64: rain relation coefficient (m/s per Z^rain_exponent), default 2.6.
  • rain_exponent::Float64: rain relation exponent on linear Z (dimensionless), default 0.107.
  • snow_coefficient::Float64: snow relation coefficient (m/s per Z^snow_exponent), default 0.817.
  • snow_exponent::Float64: snow relation exponent on linear Z (dimensionless), default 0.063.
  • density_exponent::Float64: exponent on ρ̄(0)/ρ̄(z) (dimensionless), default 0.45.
  • mixed_phase_dbz::Float64: reflectivity (dBZ) at or below which the above-melting-layer fall speed is pure snow; default 20.0.
  • rain_dbz::Float64: reflectivity (dBZ) above which the above-melting-layer fall speed is pure rain; linear blend in dBZ between the two. Must exceed mixed_phase_dbz; default 30.0.
  • melting_layer_bottom_m::Float64: height (m, grid z convention) of the melting-layer bottom. NaN (default) ⇒ derived from the reference profile's freezing level (freezing_level_m); an error is raised at use if that profile carries no temperature.
  • melting_layer_depth_m::Float64: melting-layer depth (m) over which the fall speed blends linearly in height from rain (bottom) to the above-layer value (top); default 1000.0 (samurai melting_zone_width = 1 km).
source
Daisho.GateErrorParameters — Type
GateErrorParameters

Per-gate radial-velocity error model, loaded from the optional [synthesis.gate_error] sub-table (a present table means "enabled"; every key is optional). Each gate's error standard deviation (m/s) is

σ_m = max(error_guard_min_m_s, |sin(el)|·fall_speed_error_m_s + SW·spectrum_width_error_factor)

(samurai radar_fallspeed_error / radar_sw_error / radar_min_error); the SW term is omitted when no spectrum_width-tagged field is configured or the gate has no SW value. It is folded into the gridding weight as w′ = w·σ²_vr/σ_m² (σ²_vr = velocity_variance), which keeps the stage-1 planes and sandwich covariance formula valid and reduces to the unscaled weight when absent.

Fields

  • fall_speed_error_m_s::Float64: assumed fall-speed error (m/s), scaled by |sin(el)|; default 2.0.
  • spectrum_width_error_factor::Float64: multiplier (dimensionless) on the gate spectrum width (m/s); default 1.0.
  • error_guard_min_m_s::Float64: lower clamp (m/s) on σ_m, a stability guard that keeps near-horizontal gates from receiving unbounded weight; default 1.0.

Daisho.terminal_fall_speed — Function
terminal_fall_speed(m::FallSpeedParameters, dbz, z, reference, melting_bottom_m) -> Float64

Hydrometeor terminal fall speed (m/s, negative = downward, samurai convention) for a gate of reflectivity dbz (dBZ) at height z (m), with the density correction from reference (an AbstractReferenceProfile) and the melting layer spanning [melting_bottom_m, melting_bottom_m + m.melting_layer_depth_m].

A direct port of samurai VarDriver3D.cpp (the MetObs::radar branch), with zeroClevel → melting_bottom_m, 1000·melting_zone_width (km) → melting_layer_depth_m (m), refstate rhoref → reference_density:

ZZ   = 10^(dbz/10)
DCOR = (ρ̄(0)/ρ̄(z))^density_exponent
VTR  = −DCOR·rain_coefficient·ZZ^rain_exponent
VTS  = −DCOR·snow_coefficient·ZZ^snow_exponent
above-layer value VTA: dbz ≤ mixed_phase_dbz → VTS; dbz > rain_dbz → VTR;
                       otherwise the linear blend in dbz between VTS and VTR
z < bottom            → VTR (rain for every dBZ)
z > bottom + depth    → VTA
in the layer          → VTR·(top − z)/depth + VTA·(z − bottom)/depth

The result is continuous in both dbz and z.

gate_sigma(ge::GateErrorParameters, el, sw) -> Float64
